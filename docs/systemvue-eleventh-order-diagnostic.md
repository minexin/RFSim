# RFAMP 四至十一阶受控实测

本轮把参考采集扩展到七、九、十一阶，并完成七组警告为空、参数读回与时间戳
均通过校验的 SystemVue 2023 数据。它验证固定 RFAMP 参数下的高阶来源项，
不等于实现了 RFAMP 自动高阶系数算法，也不是完整十一阶兼容验收。

## 工况与来源

首级 G=10 dB、OP1dB=20 dBm、OPSAT=23 dBm、OIP2=40 dBm、OIP3=30 dBm，
共同阻抗 50 Ω；次级 G=−10 dB，其余放大器参数相同；两级 RISO=140 dB。
关闭噪声、相位噪声、次级谱和 UseSpecReduction，ElimSpec=0，
IgnorePwrLvl=−200 dBm，通道带宽 1 MHz。只比较首级输出端口 3 的生成项。

| 最大阶数 | 输入 | 相位 | 用途 |
| --- | --- | --- | --- |
| 11 | 单音 5 dBm | 0° | 独立 H5/H7/H9/H11 校准 |
| 11 | 单音 0 dBm | 0° | 功率外推 |
| 11 | 单音 5 dBm | 45° | 复相位验证 |
| 11 | 双音各 5 dBm | 0°/90° | 全来源覆盖与公共限幅 |
| 11 | 双音 5/0 dBm | 0°/90° | 不等功率验证 |
| 7、9 | 单音 5 dBm | 0° | 最大阶数选择器对照 |

RF 频率为 1 GHz 和 1.1 GHz，每个源带宽 1 Hz。
最高驱动为双音总功率约 8.01 dBm，低于首级输入 1 dB 压缩点；
但共同非线性输入限幅已经生效，不能因为没有警告就省略工作点计算。

[数值采集](../validation/systemvue-2023-eleventh-order-captures.json)包含输入命令、
脚本、时间戳、参数、频谱数组与原始采集哈希；不包含厂商工作区。
[官方帮助来源](../validation/systemvue-2023-eleventh-order-help-provenance.json)
记录本机文档页哈希及释义。

## 截点定义与奇数阶校准

官方 RFAMP_HO 表格给出的 IM4/6/8/10 参考差频项分别是
3f1−f2、4f1−2f2、5f1−3f2、6f1−4f2。
因此不能把四阶的“n−1 个第一音减一个第二音”直接推广到全部偶数阶。
公开截点偏移对应 OIP4/6/8/10 = 33/31/29/28 dBm，
系数由已有显式截点 API 计算，未按本轮数值拟合。

五、七、九、十一阶系数只从 5 dBm、0°、最大阶数 11 的单音 Hn 识别，
后续评分排除该整组校准采集。有效电压系数约为：

| 阶数 | 有效系数 |
| ---: | ---: |
| 5 | −0.07786106164494835 |
| 7 | −0.025165406171645272 |
| 9 | −0.003912668247015405 |
| 11 | −0.00020418916642208037 |

这些值以标称源功率波为参考，可能包含很小的端口匹配/数值修正；
不能称作任意 RFAMP 参数下的精确内在系数，未写入生产器件工厂。

## 观测结果

[可重跑诊断报告](../validation/systemvue-2023-eleventh-order-diagnostic.json)
保持原有相对复波容差 1e−7，每个来源项校验两个带边样本。

| 阶数 | 独立评分项数 | 最大相对复波误差 | 结果 |
| ---: | ---: | ---: | --- |
| 4 | 42 | 约 5.0e−8 | 通过 |
| 6 | 95 | 约 7.5e−8 | 通过 |
| 8 | 176 | 略大于 1.0e−7 | 失败，处于边界附近 |
| 10 | 293 | 约 1.25e−7 | 失败 |
| 5 | 68 | 约 3.82e−9 | 校准外验证通过 |
| 7 | 136 | 约 5.35e−9 | 校准外验证通过 |
| 9 | 235 | 约 6.88e−9 | 校准外验证通过 |
| 11 | 368 | 约 8.41e−9 | 校准外验证通过 |

双音各 5 dBm 时，第十一阶有完整的 182 个来源项。
使用既有公共输入限幅比例约 0.9954103717 后，原先约 4.93% 的十一阶误差
得到解释；报告同时保留限幅前误差。这个比例来自现有工作点 API，
没有通过高阶观测反求。七、九阶选择器下保留阶数的奇数阶系数也通过验证。

0 dBm 单音有 4 个预测项未记录，5/0 dBm 双音有 6 个；均保留为缺项，
未算作零或数值通过。八、十阶名义残差已由后续[实际输入参考对照](systemvue-highorder-input-reference.md)定位，原报告失败仍保留，未放宽容差。
全部报告固定标注 diagnostic_only、eligible_for_compatibility=false。

## 采集可靠性修复与回归

高阶双音复数数组超过原采集器的 4096 标量上限。本轮将上限设为 65536，
超过时明确失败；不再静默遗漏数组。归档器对端口 2、3 的频率、功率、
身份、电压和阻抗数组做完整一致性检查。受影响的两个初次采集仍保留在
本地 build-reference 中，发布数据使用重新采集且验证通过的版本。

新增 8 项诊断回归覆盖校准污染、虚部异常、必需来源缺失、不完整实验、
参数读回和数组截断。原采集器回归补充了新阶数和 5 dBm 的参数传递，
归档回归确保静默截断不会被接受。

重放命令（先设置 PYTHONPATH=python）：

```powershell
python scripts/reference/diagnose-eleventh-order.py build-msvc/Release/rfmodel_c.dll validation/systemvue-2023-eleventh-order-captures.json build-reference/eleventh-order-replay.json
```

该命令写出报告后返回 1，因为八、十阶名义规则仍超差；这是保留的实际结果。
防误判测试通过只说明工具正确保留这些失败，不代表所有厂商数值通过。

实测结束后已恢复三阶、−30 dBm 单音、次级增益 10 dB、RISO=100 dB、
频谱削减开启的基线，并再次采集确认无警告。

## 工程验证

MSVC Debug / Release 完整 CTest 各 80/80，包含新增的 8 项高阶诊断防误判测试。
采集器参数回归 17/17，级联比较与归档回归 7/7。
独立 Python 3.12 从已安装格式 wheel 加载同一绑定，高阶诊断回归 8/8。
本轮未更改生产 C++ 核心或 Python 包，重点是实测与验证工具。

后续[高阶输入端口参考诊断](systemvue-highorder-input-reference.md)使用同一批原始采集的实际输入电压，解释了本报告八/十阶名义残差；这仍不是完整网络独立求解验收。
