# 高阶输入端口参考与残差定位

此前[四至十一阶实测](systemvue-eleventh-order-diagnostic.md)按标称源功率构造
多项式输入。八、十阶在 1e−7 的复波容差下失败。本轮从同一批原始采集中
提取首级输入端口 1 的直接源分量电压、阻抗和功率，重放同样的高阶计算；
无需新增仿真，也没有修改生产模型系数或放宽容差。

## 参考量的差别

七组实验共有九个输入源实例，每个实例保留两个带边样本。
测得端口实阻抗约为 49.99999975 Ω，而模型共同参考阻抗 Zref 为 50 Ω。

| 输入量 | 定义 | 双音各 5 dBm 工况 |
| --- | --- | ---: |
| 标称源总功率 | 2 × 10^((5−30)/10) | 0.00632455532034 W |
| 实际输送功率 | Σ P1，与 RFPwrIn 交叉验证 | 0.00632455519385 W |
| 固定参考下的多项式驱动 | Σ abs(V1_peak / sqrt(2 Zref))² | 0.00632455516222 W |

归一化输入波是实际峰值电压除以 sqrt(2 Zref)，不是 sqrt(P1)。
两者仅在实际端口阻抗等于 Zref 时相同。该组归一化波相对标称输入约为
0.9999999875，因此 n 次幂将输入差异放大为约 n × 1.25e−8；
十阶约 1.25e−7，恰是原名义输入比较中的超差量级。

公共限幅工作点也使用这些固定参考波的平方和。若只改输入波、仍把 RFPwrIn
代入工作点，双音高阶残差约为 1.7e−9；保持整个输入定义一致后进一步下降。
输出继续沿用既有 V3/sqrt(2 Z3) 厂商功率波读取约定，并独立校验 V3/P3/Z3。

这是对本组可观测输入差异的定位；SystemVue 为什么产生这些微小端口偏差，
以及 RFModel 如何从标称源和完整网络独立算出相同端口量，仍需继续研究。

## 独立证据与结果

[输入参考记录](../validation/systemvue-2023-highorder-input-references.json)
保存频率、功率、峰值复电压、复阻抗、直接源身份和原始采集 SHA-256。
它与原有七组高阶采集按哈希一一配对，缺失、重复或混用其他采集均被拒绝。
提取器先执行原有命令、参数、时间戳和端口 2/3 完整性检查，再验证端口 1
的数据维数及电压—功率关系，只归档直接源的两个带边样本。

偶数阶仍使用官方截点偏移及 IM4/6/8/10 定义，通过显式截点 API 换算。
奇数阶仍仅用一个单音校准工况识别，整个校准工况排除在奇数阶独立评分之外。
新的[实际输入诊断报告](../validation/systemvue-2023-highorder-input-diagnostic.json)
同时保留原名义输入结果摘要：

| 阶数 | 独立评分项数 | 实际输入最大相对复波误差 |
| ---: | ---: | ---: |
| 4 | 42 | 1.09e−13 |
| 6 | 95 | 1.60e−13 |
| 8 | 176 | 2.18e−13 |
| 10 | 293 | 2.69e−13 |
| 5 | 68 | 1.34e−13 |
| 7 | 136 | 1.87e−13 |
| 9 | 235 | 2.40e−13 |
| 11 | 368 | 2.94e−13 |

共 1413 项在原 1e−7 容差下通过。原名义输入报告文件保持不变；
原有 10 个低功率未记录项仍不算零或通过。报告仍固定为 diagnostic_only，
eligible_for_compatibility=false，不能把参考输入回放当作完整网络兼容验收。

## 重放与后续范围

```powershell
$env:PYTHONPATH = "$PWD/python"
python scripts/reference/diagnose-highorder-input-reference.py build-msvc/Release/rfmodel_c.dll validation/systemvue-2023-eleventh-order-captures.json validation/systemvue-2023-highorder-input-references.json build-reference/highorder-input-replay.json
```

脚本使用的输入来自已归档的实际端口数据。没有在核心中硬编码
0.9999999875，也没有把观察到的端口变化变成任意网络通用修正系数。
RFAMP 自动奇数阶系数仍未实现；本轮有效系数也不被用于生产器件工厂。
下一步仍需更多器件参数组、网络输入求解、总谱及多级非线性对照。

新增七项回归覆盖固定参考驱动与输送功率的区别、原名义失败保留、
精确采集身份绑定、数据关系错误、参考端口错误、相位污染和归档截断。

## 工程验证

MSVC Debug / Release 完整 CTest 各 81/81；新增七项输入参考诊断回归均通过。
独立 Python 3.12 从已有 wheel 加载绑定，七项新诊断回归同样通过。
本轮仅改变参考工具、测试及证据，生产 C++/Python 包无需修改。
