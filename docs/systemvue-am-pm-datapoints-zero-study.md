# DataPoints 零 dBm / 首节点判别实验

本阶段针对 SystemVue 2023 RFAMP DataPoints 模式的既有反例：原三点表在名义输出 0 dBm（恰为首节点）返回零相移，而邻近点与自然三次样条候选接近。当前目标是区分异常位置、普通分析与 Quick Sweep 的相位关系；完整 DataPoints 厂商兼容仍未成立。

## 采集前冻结

[预登记计划](../validation/am-pm-datapoints-zero-plan-20261013.json)规定七组配置、387 个登记扫描点和七个普通工作点，最多七次正常分析及一次仅用于明确配置修复的预留调用。相位容差固定为 `1e-5°`，基线功率相对容差为 `1e-7`。不重拟合，不删除零点，不因数值不符重跑。

|配置|输出功率节点 dBm|相位节点 °|增益 dB|普通目标 dBm / 源相位 °|名义扫描输出 dBm|
|---|---|---|---:|---|---|
|原三角表|0, 10, 20|10, 40, −20|20|0 / 0|−5 至 25，步长 0.5|
|首节点负值|−5, 5, 15|10, 40, −20|20|0 / 37|−10 至 20，步长 0.5|
|首节点正值|5, 15, 25|10, 40, −20|20|5 / −45|−2.5 至 27.5，步长 0.5|
|零值为内部节点|−10, 0, 10|15, 35, −25|7|0 / −29|−15 至 15，步长 0.5|
|恒相位、损耗|−5, 5, 15|20, 20, 20|−3|0 / 123|−10 至 20，步长 0.5|
|单位增益|0, 10, 20|10, 40, −20|0|0 / 63|−5 至 25，步长 0.5|
|零点密集邻域|0, 10, 20|10, 40, −20|20|0.001 / 0|−0.01 至 0.01，步长 0.001|

正首节点配置同时移动首节点的扫描序号，并在普通工作点直接测量首节点。其余非零源相位和增益/损耗配置检验源相位叠加及异常是否依赖增益。三个候选均按实测输出功率计算自然三次样条；两个旁路候选分别只在登记的名义零 dBm 或首节点处设零增量。这是有限判别规则，不是已辨识的厂商数值条件。

普通 DCP、普通原始频谱 V/Z/P、Quick Sweep DCP 分开评分；输入相位来自各自实测节点，Quick Sweep 输入相位必须为零。最多一个连续额外终点单独保留。首组的普通零点、扫描与历史普通点、扫描与历史 Compression Curve 的共享点分成三类，共 12 项基线比较；全部通过后才允许第二组分析。

本地助手在独立工作区副本中仅替换明确的 XML 字节区间，运行前核对 17 个参数及字面量表格的 `[1,N]` SI 数组形状。每次调用之后保存明确完成标志、诊断、原始结果及唯一结果工作区；辅助进程或归档校验失败将阻止后续配置。最终恢复原始工作区并比对两种模式的源、放大器、扫描参数表达式和值，保留用户的 SystemVue 进程。

旧的两个基线 JSON 在现有本地归档中为 CRLF，而 Git 曾将它们转成 LF。此次通过 `.gitattributes` 冻结现有 CRLF 字节；已核对差异仅为换行、JSON 内容完全相同，原归档哈希继续有效。新计划、单次捕获归档器和候选评分器在任何本轮分析之前提交；完整采集链归档器和真实数据回归在采集完成后加入。

## 实测结论

SystemVue `2023.0.0.11903` 完成七次登记分析，预留调用未使用；七次均明确完成且错误/告警列表为空。387 个登记扫描点、七个普通工作点以及七个额外扫描终点全部保留。额外终点对三个候选均通过，但不计入登记集合的通过率。首次分析的 12 项基线比较全部匹配，最大功率相对差 `7.40e-11`、相位差 `5.83e-9°`；这包含普通复现、扫描对普通、不同扫描模式三类比较，不等同于复现完整历史扫描。

|冻结候选|扫描 DCP（387 点）|普通 DCP（7 点）|普通原始频谱功率（7 点）|
|---|---:|---:|---:|
|自然三次样条|376|1|2|
|名义零 dBm 旁路|383|6|7|
|名义首节点旁路|375|2|3|

表中为通过点数，容差始终为 `1e-5°`。三个候选均未通过完整扫描 DCP 集合；普通原始频谱的七点通过不能替代扫描数据或证明任意表格算法。名义零旁路的扫描最大误差为 `0.0209994253°`，普通 DCP 最大误差为 `0.0052494252°`。

异常位置跟随本次登记的名义输出零 dBm，而不跟随首节点：移至 −5、+5、−10 dBm 的首节点分别给出约 10°、10°、15°增量。普通零点的源相位 37°、−29°、123°、63°得以保留，归零的是 AM/PM 增量。增益 20、7、0、−3 dB 的对照均支持该有限位置判断；它不确定内部旁路数值条件。

密集扫描中，名义 −0.004 至 +0.004 dBm 的九个点都报告 DCP 输出功率 **`0.001 W`**，相位却不同：负侧为约 10°、零点为 0°、正侧约为 10.0052494° 至 10.0209994°。在固定表格及源相位下，DCP 功率本身不足以唯一确定观察相位。名义零旁路的四个扫描失败点正是 +0.001、+0.002、+0.003、+0.004 dBm；没有改用名义功率或普通原始功率修补扫描横轴。

普通 +0.001 dBm 点的原始功率支持连续样条相位，但普通 DCP/原始功率相对差约 `2.30e-4`。单位增益普通点也存在约 `2.05e-7` 的差值，密集点并非唯一报表差异。扫描逐点原始载波功率仍未取得，不能借普通数据声称已知内部查表功率。

## 采集链与恢复

每份独立工作区均核验 17 个登记运行参数，完整保存调用意图、完成状态、原始节点、源代码快照、分析后工作区及 SHA-256。采集前计划与工具已提交；第一组的基线校验通过后才执行后续组。未重拟合，未删除不匹配点，未为数值不符重跑。

两次工作流校验失败及其离线修复完整保留。最初停放检查发现两个模式的 `DigNumAvg` 存在同路径双重参数项，原字典会覆盖其中一项；修复为保留全部有序重复项，并在第一次分析前提交。最终重新打开原始工作区后，247 个参数项的值、表达式、数组形状已经全部一致，但 117 项惰性生成的 `Data:type` 元数据尚未出现，第一次严格比较仍失败。随后只读复查确认全部 245 个路径、247 个有序参数项连同元数据完全一致；没有额外分析、保存或关闭。原始工作区 SHA-256 保持不变，用户原有 SystemVue 进程继续运行。
